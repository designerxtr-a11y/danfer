# Calendario Machu Picchu 2027: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** página `/disponibilidad-machu-picchu-2027` (ES/EN/JA) con calendario 2027, ruta y hora, pasajeros con foto de documento, y pago completo por PayPal, que deja la reserva en Admin › Reservas.

**Architecture:**
- Datos y precio en `src/lib/mp2027/` (puro y testeable).
- Página estática con un componente cliente `Mp2027Booking`.
- Server actions validan con zod, recalculan el monto y crean la reserva `pending/unpaid` antes de abrir PayPal.
- Al capturar, se verifica el monto y se marca `confirmed/paid`.
- Detalles (ruta, hora, pasajeros, PayPal) en `special_requests` como JSON. Sin migración: no hay credenciales de BD en `.env.local`.

**Tech Stack:** Next 16 App Router, next-intl, Supabase (service role en server actions), PayPal REST (`src/lib/paypal.ts`), zod 4, `node --test`.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-11-07-calendario-mp-2027-design.md`.
- Precio: US$380 por persona, +5% por tarjeta, total redondeado a 2 decimales. El servidor es la única fuente del monto.
- 1 a 10 pasajeros. Foto de documento obligatoria por pasajero.
- Fechas válidas: de 2027-01-01 a 2027-12-31.
- La página pública sale ● en `next build`. Nada de cookies ni headers en ella.
- Textos en ES/EN/JA con `L()` (`src/lib/i18n/pick.ts`). Mensajes de WhatsApp en EN para `ja`.
- Sin emojis en la interfaz nueva.

### Task 2: server actions

**Files:** Create `src/app/[locale]/(public)/disponibilidad-machu-picchu-2027/actions.ts`.

**Interfaces (Produces):**
```ts
uploadMp2027Doc(draftId: string, travelerIndex: number, formData: FormData): Promise<{ok:true}|{ok:false;error:string}>
createMp2027Order(input: Mp2027Input): Promise<{ok:true; orderId:string; code:string}|{ok:false;error:string}>
captureMp2027Order(orderId: string): Promise<{ok:true; code:string}|{ok:false;error:string}>
```
`Mp2027Input` (zod):
- `draftId`: `/^[a-z0-9]{10,24}$/`.
- `date` (`isValid2027Date`), `route` (RouteId), `hour` (dentro de `route.hours`).
- `travelers[]` 1..10 de `{ fullName, docType: "passport"|"dni", docNumber, nationality, birthDate }`.
- `email`, `whatsapp`, `hotel?`, `acceptPolicy: true`, `lang`.

- [ ] `uploadMp2027Doc`: mismas validaciones de tamaño y tipo que `uploadPassportPhoto`. Guarda en `client-documents` como `mp2027-${draftId}/traveler-${i}-${Date.now()}.${ext}`.
- [ ] `createMp2027Order`:
  - Validar con zod y comprobar en Storage que hay al menos una foto por pasajero (listar `mp2027-${draftId}` y buscar el prefijo `traveler-i-`). Si falta alguna, devolver `{ ok: false, error: "missing_doc:i" }`.
  - Calcular `mp2027Total(n)` y buscar `tour_id` por slug `machu-picchu-2d-1n`.
  - Insertar en `bookings`: `travel_date` = date, `travelers` = n, subtotal, `total_amount` = total, `customer_name` = travelers[0].fullName, email, phone = whatsapp, `status: "pending"`, `payment_status: "unpaid"`, `special_requests` = JSON `{ kind: "mp2027", route, hour, hotel, draftId, lang, travelers }`.
  - `createPaypalOrder(total, "USD", "Machu Picchu 2D/1N 2027 · " + date + " · Ruta " + route + " · " + code)`.
  - Guardar `internal_notes = "paypal_order:" + orderId` y devolver `{ orderId, code }`.
- [ ] `captureMp2027Order`:
  - Buscar la reserva por `internal_notes = "paypal_order:<id>"`.
  - Si ya está `paid`, devolver ok (idempotente).
  - Hacer `capturePaypalOrder`. Si `status !== "COMPLETED"`, error.
  - Leer el monto capturado (`purchase_units[0].payments.captures[0].amount.value`) y compararlo con `total_amount`. Si no coincide, poner `internal_notes += " amount_mismatch"` y devolver error. Si coincide, actualizar a `confirmed/paid`.
  - Para leer el monto, ampliar el tipo de retorno de `capturePaypalOrder` (sin cambiar su comportamiento).
- [ ] `npx tsc --noEmit -p .` limpio. Commit `feat(mp2027): server actions with server-side pricing and capture check`.
